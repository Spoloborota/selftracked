## Scope restated from the spec (re-read at open)

1. **The §8.6 gate becomes real.** Two ordered comparisons at the start of
   every verb, before the §8.4 divergence check: (i) tracked dump header
   `schema_version` vs the binary's N — newer is the forward-only exit-2
   refusal naming the required upgrade; then (ii) DB `user_version` vs N —
   older triggers migration. `load` on a fresh clone has no DB to gate:
   (i), then rebuild.
2. **The migration engine** (policy machinery — v0 ships schema version 1,
   the first transform is written when v2 exists): per historical version
   k the binary compiles DDL(k), whitelist(k), transform T_k; migration
   hydrates rows (live DB or old dump — same engine, two sources), runs
   the transform chain, builds a fresh DB from DDL(N) through the load
   path (INSERT-firing gates bind hydration: serializer PK order, worklog
   seq contiguity), verifies, atomically renames, and only re-serializes +
   updates the sidecar when §8.4 finds no external change.
3. **Escalation choreography.** A read verb finding `user_version` behind
   escalates for the migration only: write connection, EXCLUSIVE lock,
   migrate, reopen read-only — so the first post-upgrade `prime`
   (SessionStart) migrates. Race: the loser blocks on the lock, re-checks
   `user_version` after the wait, proceeds read-only; a BUSY surviving
   `busy_timeout` exits 2 with a retry hint.
4. **§8.4 branches (5)–(6).** (5) dump matches sidecar but DB
   `user_version` is ahead of the dump header — migration-crash residue,
   healed by re-running the re-dump. (6) a migration triggered in the
   externally-changed state completes DB-side only and does not write the
   dump.
5. **Surfacing.** The migration notice line always goes to stderr (no
   output-limiting flag suppresses it); `prime` populates the S8c-built
   `migrated: "vK→vN"` slot (absent on a non-migrating invocation).

Verification, per the frozen plan's S11 row: refusal fixtures at `load`
and `prime` (typed field); escalation-race/busy fixtures; branch-(5)/(6)
fixtures driven by a synthetic version bump; a migrating `prime` emits
`migrated:vK→vN`, absent otherwise. The §16 golden old-dump corpus starts
at schema version 2 — v0's obligation is the refusal fixture for N+1 and
the machinery itself.

## What already exists (verified at open)

- The dispatcher routes every verb through a gate stub with the final
  call shape (`internal/cli/dispatch.go` + `internal/cli/gate.go`); the
  write/read pipeline carries a second stub (`internal/verb/pipeline.go`,
  `versionGate()` returning nil).
- Comparison (i) exists in two partial forms: `load`'s parser refuses a
  newer or unknown header version (`internal/load/parse.go`), and `prime`
  reports `dump_requires_newer_binary` read-only
  (`internal/verb/prime.go`). No other verb runs any comparison.
- The `migrated` contract slot exists (`omitempty`, never populated —
  amendment `migrated-field-rides-migration-at-s11`).
- `divergenceCore` implements the non-migration §8.4 matrix only: it
  never reads `user_version`; branches (5)–(6) are absent.
- `internal/schema` compiles `Version = 1` with a literal identity stamp
  (`stampSQL`), kept honest by `TestStampMatchesTheConstants`.

## Watch-items taken into the stage

- **The synthetic-bump test seam.** With only v1 real, migration paths
  are exercisable only through injected synthetic versions. The
  white-box override-var pattern is already established in the pipeline
  (`stateRender`, `traceStep`); the seam must not weaken the production
  path (a test-only registry entry must not be reachable in a shipped
  binary's normal flow).
- **"Stage-0 + full verify" ordering inside the migration.** §8.6 places
  full verify before the atomic rename, but R1/R14 compare instance
  files that are only rewritten after the rename (the re-dump tail). The
  implementable reading must be pinned down against §7's rule scoping
  during the build; if the letter cannot be implemented as ordered, that
  is an amendment question, not a silent choice.
- **Gate scope across the catalog.** The gate is specified for "every
  verb"; whether `version`/usage surfaces (which do not operate on the
  repository) refuse too is a semantics question to resolve against
  §6.2's catalog — flagged here so the decision is recorded, not
  implicit.
- **`meta.schema_version` during rebuild.** The dump carries no PRAGMAs;
  identity is stamped from the meta row (§8.5). The engine must leave
  the rebuilt DB's meta row at N or the next verb re-migrates a current
  DB.

## Close appendix (2026-07-24)

The stage landed in three implementation commits (87638b0 the engine,
then the close-review fix batch, 32dcb18 the second amendment's
application) behind two proposal-first amendments, both owner-ratified
the same day: `migration-verify-battery-is-the-load-battery` (spec rev
3.22 — the watch-item from this record's own list: R1 cannot pass before
the re-dump exists, so the pre-rename battery is §8.5's) and
`migration-gate-mechanics` (rev 3.23 — the §3.1 lock-posture carve-out,
the sentinel protocol, the DB-ahead refusal, the sidecar-anchored
pre-swap snapshot). The other watch-items resolved: the synthetic-bump
seams (`migrate.currentVersion`, `load.current`, `verb.GateVersion`,
`load.Steps`) are written to only by sequential tests and restored in
cleanups, with no production assignment (grep-verified by the security
critic); the gate-scope question dissolved — the catalog has no
`version` verb, and `-h` returns before the gate.

**What the build itself proved by failing first:** SQLite's busy handler
deadlocks two racing gates (each holds the SHARED lock it acquired while
waiting for the other's RESERVED/EXCLUSIVE), and `locking_mode=EXCLUSIVE`
makes it permanent by keeping locks sticky past a FAILED `BEGIN` — both
reproduced with an instrumented probe before the fail-fast acquisition
design replaced them. The escalation race then resolved in ~11 ms with
exactly one winner across repeated runs.

**The review (plan §5, FULL).** Three fresh critics — spec fidelity,
concurrency/correctness, security boundary — 31 findings, adjudicated
refute-by-default with load-bearing claims reproduced by hand. Nine
accepted and applied, sharpest: the close review's own cyclop refactor
had moved the loser's outcome-interpretation ahead of its ROLLBACK, so a
losing gate blocked its fresh re-check against its own EXCLUSIVE
transaction for the whole busy budget (driver-level reproduction); a
failed swap rename left the database sentineled forever with a
data-discarding `load --force` as the only exit (now `restoreMark`
un-marks and the next verb re-migrates); three divergent header parsers
became one (`dump.HeaderVersion`/`TrackedHeaderVersion` — prime's copy
had skipped the prefix and v≥1 guards, the gate's scanner silently
swallowed token-too-long); `grammarFor` resolves the current version
compiled-in-first so no registry entry can shadow the byte-equal DDL
gate; `.gitignore` patterns widened to `db.sqlite*`. New proofs added at
the critics' insistence: migration commutativity across the two
hydration sources (byte-identical serializations), the
`worklog_seq_contiguous` abort on a renumbering transform's mistake,
branch-(5) heal through a real `prime` invocation, swap-failure
recovery. Refuted with reasons on the record: busy-handler waits in
plain reads are §3.1's sanctioned contract; the emitted-tables check
does what its message says (an absent new table is legitimately empty);
`Literal` narrowing past a Transform stays convention — parameterized
inserts hold the boundary.
