into a tracker: it creates `.selftracked/{db.sqlite,dump.sql,dump.hash}`

## Scope boundaries (what S8a does NOT do)

Named so the review does not read the absences as gaps:

- **Hooks are S8b.** §9's tree shows `.selftracked/hooks/`, but plan §4
  gives the generated pre/post-commit, the chaining recipe, and `gate
  skip-mark` to S8b. `init` at S8a scaffolds everything else; the `hooks/`
  content lands when S8b extends `init`. A fresh tracker with no chained
  hooks still verifies green — R11 (the hook rule) is advisory, so its
  warning never fails the run — which is exactly why "fresh `init` ⇒
  `verify` green" (INV-402/493) holds before the hooks exist.
- **The `state` verb, `prime`, and the SessionStart runtime chain are
  S8c.** S8a generates the `.claude/` rule and skill as shipped text, and
  the SessionStart settings file as a static string (it names `selftracked
  prime` — a command string, writable before the verb exists). S8c builds
  `prime`/`state` and tests the three-branch chain behaviour.
- **R14 / R1 check 3 (STATE.md byte-equals its render) is S8c** (amendment
  `r14-rides-its-renderer-at-s8c`). S8a writes STATE.md and proves its
  renderer deterministic; the verify-time comparison rides S8c.

## Cross-stage dependency resolved here: the STATE.md renderer

INV-414 makes `init` generate a **deterministic** STATE.md, and that word
demands a renderer — the same renderer INV-274 (the S8c `state` verb) and
R14 (S8c) consume. `init` is its FIRST consumer, so the renderer is born
here: a `internal/state` package (a pure DB→bytes function, fixed sections,
fixed ordering, last 10 events), which S8c's `state` verb and R14 reuse via
the `stateRender` hook already stubbed in the pipeline. Building the render
FUNCTION at S8a is not stealing INV-274's row — that row is the `state`
VERB (its flag surface, events, the SessionStart wiring), which stays S8c.

## Notable realizations

- **`init` grows across S8a→S8b→S8c.** It is one verb, generated in layers:
  docs+scaffold here, hooks at S8b, the SessionStart config's runtime
  meaning at S8c. Each layer adds output; none rewrites a closed layer's.
- **Meta seeding already exists.** `schema.Create` seeds the five meta rows
  (schema_version, events_archived_through, production_globs, idle_days,
  prime_cap). `init` builds the DB through `schema.Create`, so INV-418 is
  satisfied by that path — `init` adds no second seeder.
- **The generated `.claude/` is the ADOPTER's, not this repo's.** This
  repo's own `.claude/` is dev tooling; `init` writes a fresh, shipped
  `.claude/` into the target repo. Fixtures run in temp dirs, so the two
  never touch — but the generated content is authored from §11, never
  copied from this repo's files.

## What this open did not do

No code was written. Close-review seams to watch: (1) STATE.md's renderer
must be byte-deterministic across two calls with no intervening writes, or
R14 at S8c is built on sand; (2) the golden files must be regenerated FROM
the code, never hand-edited to match, or they test nothing; (3) every
"assert the text is present" row needs the ACTUAL required sentence, not a
paraphrase, or the durable-doc rules ship subtly wrong; (4) `init --force`
must not silently destroy a populated tracker — its overwrite scope needs
stating.
