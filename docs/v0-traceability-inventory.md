## Column contract

| Column | Meaning |
|---|---|
| `INV-###` | Stable row id. Referenced by stage closure lists and, after S10, by the imported story/criterion records. |
| `anchors` | Every spec section the obligation lives in; cross-section obligations list all of them. |
| `statement` | The obligation in one line. |
| `kind` | schema-gate · verb-contract · catalog-convention · verify-rule · format · process · deliverable · stated-limitation · deferral-boundary |
| `stage` | The stage whose closure list owns this row (plan §4), or `deferred` / `spec-record`. |
| `verification` | The command or fixture that will prove it. Suggested at extraction time; a stage may refine it, never drop it. |
| `status` | `planned` → `verified-by-command` (plan §5). |
| `evidence` | CI run URL or committed log artifact proving the verification actually ran. Empty until the closing stage fills it; a `verified-by-command` row with no evidence is a defect the accounting check rejects. |

A `verification` value prefixed `review:` marks an obligation no fixture
can prove (an interpretive or risk-equivalence claim). Those rows are
closed by a recorded review at their stage, never by a command — and the
accounting check counts them so the proportion stays visible.

### Scope boundary

The inventory walks the specification. A stage's definition of done may
also contain plan-native work — artifacts the execution plan itself
created, such as retiring the progress ledger and this inventory at S10 —
which no row can carry by construction. Those items are closed by the
stage's review pass, not by the accounting rule, so a stage's row count
understates its scope wherever that applies (today: S10 alone).
